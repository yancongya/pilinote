# doc-map:review

检阅文档链路方案，评估是否需要优化。

## 触发

用户明确说"检阅 XXX"

## 流程

1. 加载 docs/.doc-map.json
2. 分析问题涉及哪些目录/文档
3. 检查链路完整性
   - 验证引用的文档是否存在
   - 验证依赖关系是否正确
4. 评估链路方案
   - 文档内容深度够不够
   - 文档组织结构是否合理
   - 引用关系是否最优
5. 如需优化且模块较大，调用 project-documentation-workflow
6. 否则只补充缺失的文档碎片
7. 输出简单扼要回复

## 评估标准

| 维度 | 检查内容 |
|------|----------|
| 内容深度 | 文档是否详细描述功能？是否有遗漏的关键点？ |
| 组织结构 | 文档分类是否合理？是否便于查找？ |
| 引用关系 | 链接是否正确？是否有断裂的引用？ |

## 输出格式

直接简单回复，如：
```
根据检阅结果：
- auth/ 模块文档完整，链路正确
- download/ 模块缺少 scheduler.md 详细文档，建议补充
```

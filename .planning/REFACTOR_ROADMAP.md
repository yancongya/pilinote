# PiliNote 渐进式整理

## 执行约束

- 用户授权分阶段 commit；不自动推送。
- 执行代理使用 GPT-5.6 Terra / low，盘点使用 GPT-5.6 Luna / low，独立审查使用 GPT-6 Sol / low。
- 前端和后端按目录隔离，执行代理不操作 Git；协调者验证后按明确文件清单提交。
- 工作区开始时已有暂存迁移、文档删除、技能删除和测试迁移。保留这些变更，不纳入本轮提交。
- 不改认证、下载协议、数据库结构或产品行为；不安装新框架。

## 第一阶段：基线和整理计划

交付本计划、模块及测试现状盘点。现有代码包含 Vitest、Playwright 和 Python 测试；AGENTS.md 中“无正式测试”和文档目录信息需要后续校准。

验收：明确任务文件范围、已有改动隔离方式，以及每次变更的验证结果。

## 第二阶段：前端职责提取试点

从一个大文件中提取边界明确的纯工具逻辑，保留调用接口和交互。优先使用已有测试覆盖的路径。

验收：针对性测试、前端构建；环境缺失或基线失败须明确记录，不能标为通过。

## 第三阶段：后端职责提取试点

从一个服务中提取纯逻辑，保留对外接口；按需补充独立单元测试。避免真实网络、认证和生产数据库。

验收：已有虚拟环境中的针对性测试；缺少运行环境时记录限制，并执行可用的静态检查。

## 第四阶段：审查和阶段记录

GPT-6 Sol / low 独立审查两项试点，协调者处理发现并记录实际验证、提交和后续优先级。

验收：每阶段独立 commit，仅包含该阶段文件；原有暂存内容保持原状。

## 后续阶段

根据试点结果逐项规划视频详情、AI 笔记和下载队列整理。每个任务指定职责、文件范围、接口兼容和验收条件；依赖检查工具在业务边界明确后引入。

# 收藏/稍后再看/历史记录统一列表设计

## Summary

将收藏页、稍后再看页和观看历史页统一为同一套“历史型视频列表”组件和交互规范。三页继续保留各自的数据源、筛选条件和业务动作，但页面壳、列表状态、骨架态、空状态、加载更多和刷新提示收敛到统一的前端基础层。

本设计不追求把三页合并成一个无差别的大页面，而是把它们统一到同一套列表系统上，让后续的 UI 升级、懒加载、缓存和移动端适配都能一次改动覆盖三页。

## Goals

- 统一收藏页、稍后再看页、历史记录页的列表壳和交互规范。
- 统一首屏加载、后台刷新、加载更多、空状态和错误状态的展示方式。
- 保留三页各自的数据适配层、筛选项和下载相关业务逻辑。
- 让后续升级视频列表 UI 时优先改公共组件，而不是逐页改样式。

## Non-Goals

- 不重写视频卡片内部的全部字段展示。
- 不改变收藏、稍后再看、历史记录的后端 API 数据结构。
- 不把三页强行改成同一个业务页面。
- 不引入新的状态管理库或复杂 schema 驱动配置。

## Architecture

### Shared List Shell

新增一层统一的列表壳，负责承载三页共同的页面结构：

- 页面标题和视频数量统计
- 筛选条
- 首屏骨架
- 后台刷新提示
- 加载更多骨架
- 空状态
- 错误状态

这一层只处理布局和状态切换，不关心具体视频来源。

### Page Adapters

三页各自保留独立的适配层：

- `FavoritesContent`
- `WatchLaterContent`
- `HistoryContent`

它们负责：

- 调用各自的 API
- 把响应映射成统一的视频项格式
- 处理各自特有的下载逻辑
- 提供自己的排序项和筛选默认值

### Common Interactions

三页共用同一套交互规范：

- 首次进入列表时显示骨架
- 列表已有数据时后台刷新不清空内容
- 滚动到底部时触发加载更多
- 没有数据时显示统一空状态
- 搜索和排序变更后回到第一页并重新加载

### Shared State Model

列表页统一采用相同的状态语义：

- `loading`: 首屏加载中
- `loadingMore`: 加载下一页中
- `error`: 当前列表错误
- `hasMore`: 是否还有下一页
- `total`: 总数量
- `videos`: 当前页及已加载的视频集合

这套状态由 `useVideoList` 继续提供，页面层只负责把它映射到统一 UI。

## Implementation Scope

### 1. 抽出统一列表壳

把三页的重复结构收敛为一个统一壳层，建议职责如下：

- 接收页面标题、统计信息和筛选条配置
- 接收统一的状态对象
- 决定何时展示骨架、空状态、错误状态、刷新提示
- 保持视频列表主体区域稳定，避免空白闪跳

### 2. 统一筛选和操作条

收藏、稍后再看、历史记录都继续使用同类筛选能力，但统一交互行为：

- 搜索框回车提交
- 排序选择后立即或显式触发刷新，保持三页一致
- 排序方向切换统一为同一个按钮语义
- 若页面支持刷新按钮，则按钮位置和样式一致

### 3. 统一加载骨架

三页共用同一套首屏骨架和加载更多骨架：

- 首屏加载：页面级骨架，覆盖标题和内容区
- 已有内容刷新：保留当前列表，仅显示轻提示
- 加载更多：列表底部显示较小骨架，不清空现有数据

骨架布局允许少量密度差异，但不允许三页各自定义完全不同的加载态。

### 4. 统一空状态与错误状态

空状态和错误状态统一为公共组件或公共渲染逻辑：

- 空状态：无收藏、无稍后再看、无历史记录、无搜索结果
- 错误状态：网络错误、接口异常、限流提示

三页只保留各自的文案，不再各写一套独立空态排版。

### 5. 保留页面级差异

以下内容保留在页面适配层，不进入公共壳：

- 收藏页的文件夹切换和懒加载缓存 key
- 稍后再看页的 `add_time` 排序和进度展示
- 历史记录页的 `view_time` 排序和观看时间展示
- 各页自己的下载检查、重新下载提示、跳转行为

## Files and Responsibilities

### Shared UI Layer

- `apps/web/src/components/VideoListContainer.tsx`
  - 承担视频列表主体容器职责，收敛通用加载态和空状态。
- `apps/web/src/components/VideoCardSkeleton.tsx`
  - 承担统一骨架态，支持首屏骨架和加载更多骨架的不同密度。
- `apps/web/src/components/VideoListControls.tsx`
  - 承担统一筛选条和刷新交互。

### Page Adapters

- `apps/web/src/pages/components/FavoritesContent.tsx`
  - 收藏页适配层，接入统一列表壳和缓存策略。
- `apps/web/src/pages/components/WatchLaterContent.tsx`
  - 稍后再看页适配层，接入统一列表壳和筛选/排序规范。
- `apps/web/src/pages/components/HistoryContent.tsx`
  - 历史记录页适配层，接入统一列表壳和筛选/排序规范。

### Cache Layer

- `apps/web/src/stores/cache.ts`
  - 保存收藏页视频列表缓存，按收藏夹和筛选条件组织缓存键。

### API Layer

- `apps/web/src/services/api.ts`
  - 让收藏夹详情支持 `lazy` 参数，默认走轻量返回。
- `apps/api/src/routers/favorites.py`
  - 收藏夹详情默认只返回基础数据，按需才做完整补全。

## Data Flow

```
页面适配层
  -> apiService 获取当前页数据
  -> useVideoList 统一分页与无限滚动
  -> Shared List Shell 统一渲染状态
  -> VideoListContainer 渲染视频卡片或骨架
```

收藏页额外包含缓存分支：

```
收藏页适配层
  -> 先查 folderVideosCache
  -> 命中则直接渲染
  -> 未命中则请求后端 lazy 接口
  -> 请求成功后写回缓存
```

## Testing

### Functional Checks

- 收藏页首次进入时先显示骨架，不出现白屏。
- 收藏页命中缓存时可以直接渲染列表，不重复等待后端补全。
- 稍后再看页和历史记录页保持原有分页、排序和下载交互。
- 三页的加载更多、空状态和错误状态样式一致。

### Regression Checks

- 收藏页的文件夹切换和返回列表行为不变。
- 稍后再看页的排序与下载状态展示不变。
- 历史记录页的排序与下载状态展示不变。
- 移动端下三页的列表滚动和骨架布局正常。

### Acceptance Criteria

- 三页的页面壳看起来属于同一套产品语言。
- 三页的加载态、空状态、错误态和加载更多行为统一。
- 新增一个视频列表页时，可以直接复用这套列表系统，而不是重建一套新的交互。

## Assumptions

- 本次只统一“列表组件和交互规范”，不统一所有卡片内部字段和业务按钮。
- 收藏页、稍后再看页、历史记录页仍由各自页面文件负责数据适配。
- 现有 `useVideoList` 继续作为分页与无限滚动的基础设施。
- 当前的移动端 Material 风格可以继续作为三页统一视觉基线。

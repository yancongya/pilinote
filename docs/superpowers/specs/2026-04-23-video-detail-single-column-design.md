# 视频详情页单列流式重设计方案

**Date:** 2026-04-23  
**Status:** Draft  
**Goal:** 将 `VideoDetailPage` 重设计为 PC 和手机统一的单列流式详情页，整体观感更接近 B 站 App，但不修改、不删除任何现有功能内容。

## 背景

当前视频详情页仍保留明显的“PC 双列 / 手机单列”混合结构。虽然功能齐全，但视觉节奏偏碎，信息区块分散，和 B 站 App 的连续浏览体验不一致。

本次重设计只调整布局、信息层级、间距和视觉节奏，不改变数据接口、不改变功能入口、不改变内容字段。页面仍需保留：

- 视频 / 图文两种媒体类型
- 本地视频播放
- 本地图文优先渲染
- 下载与重新下载流程
- 分 P 列表
- 评论展示
- AI 笔记子路由 `Outlet`

## Goals

- PC 和手机共用同一套单列流式结构。
- 视觉上更接近 B 站 App 的“内容流”阅读方式。
- 保留现有全部功能，不缺失任何入口或信息。
- 提升详情页的层级感、可扫读性和连续滚动体验。
- 让布局升级主要通过组件重排完成，而不是改业务逻辑。

## Non-Goals

- 不修改详情页 API 语义。
- 不删除分 P、评论、本地播放、下载、AI 笔记等功能。
- 不引入新的数据来源或状态管理方案。
- 不重写视频/图文内容生成逻辑。
- 不把详情页改成左右双栏信息面板。

## Design Principles

1. **单列优先**
   - PC 和手机都遵循同一条自上而下的阅读路径。
   - 桌面端只放宽内容宽度，不恢复双栏分区。

2. **内容流连续**
   - 页面像 App 信息流一样自然下滑。
   - 各区块之间保持统一的卡片节奏和间距。

3. **功能完整可见**
   - 所有现有功能都必须在单列中找到稳定位置。
   - 不能把下载、分 P 或评论挤到不易发现的位置。

4. **视觉克制**
   - 强调封面、标题、作者、数据、操作、正文、评论的顺序。
   - 避免同时出现过多强调色和多层背景。

## Proposed Layout

页面采用以下从上到下的单列结构：

1. **Sticky 顶栏**
   - 左侧返回按钮
   - 中间标题
   - 右侧保留最少量页面级动作

2. **主视觉封面卡**
   - 视频封面或图文封面作为首屏视觉中心
   - 叠加时长 / 图文标识 / 本地播放提示
   - 封面点击仍保留本地播放能力

3. **信息卡**
   - 作者头像与名称
   - 发布时间
   - 核心统计信息
   - 统一使用单列卡片，不再左右拆分

4. **操作卡**
   - 下载 / 重新下载
   - 本地播放相关动作
   - 分 P 摘要入口
   - 该卡片只承载操作，不混入正文信息

5. **视频简介 / 图文正文**
   - 视频描述独立成卡
   - 图文正文作为连续阅读区域直接向下展开
   - 本地 Markdown 优先时，仍使用相同视觉结构

6. **分 P 列表**
   - 多 P 视频单独成卡
   - 以列表形式向下排列，不再占用侧栏
   - 保留播放本地文件、队列状态、已下载状态

7. **评论卡**
   - 热门评论保留，最多展示现有数量上限
   - 作为正文之后的独立模块出现

8. **AI 笔记子路由出口**
   - 保留 `Outlet`
   - AI 内容仍由子路由承载，不塞进主详情正文流

## Section Behavior

### 1. Sticky 顶栏

顶栏只保留必要元素，避免占用过多垂直空间：

- 返回按钮
- 标题单行省略
- 可选的轻量页面状态入口

顶栏的目标不是“导航中心”，而是“页面定位锚点”。它应该轻、窄、稳定，滚动时提供方向感即可。

### 2. 主视觉封面卡

封面卡承担首屏主视觉职责：

- 视频：显示封面、时长、本地播放提示
- 图文：显示封面、图文标识
- 保留封面点击触发本地播放
- 圆角、阴影、遮罩风格更接近 B 站 App 的移动端封面卡

### 3. 信息卡

信息卡把作者与统计信息合并到一个连续区块中：

- 作者头像和名称置顶
- 发布时间紧随其后
- 统计信息以紧凑网格或横向分组呈现
- PC 和手机都使用同一信息顺序，只调整密度

### 4. 操作卡

操作卡只解决“动作”，不承担信息展示：

- 下载 / 重新下载
- 本地播放相关提示
- 多 P 视频的总体状态
- 与下载队列相关的可见状态

按钮样式应保持 App 风格的实心主按钮 + 次级文字/描边动作，不回到旧式大而散的桌面按钮组。

### 5. 内容区

内容区分为两类：

- 视频：简介卡 + 分 P 卡 + 评论卡
- 图文：正文连续流 + 必要的元信息 + 下载按钮

图文和视频共享同一套纵向卡片骨架，区别只在内容来源和是否显示分 P / 评论模块。

## Components

### Page Shell

`VideoDetailPage` 继续负责：

- 路由参数解析
- 数据请求和错误状态
- 本地播放映射
- 下载状态同步
- AI 子路由承载

### Suggested Subcomponents

如果需要拆分，建议按职责拆成以下逻辑块：

- `VideoDetailStickyHeader`
- `VideoDetailHeroCard`
- `VideoDetailInfoCard`
- `VideoDetailActionCard`
- `VideoDetailDescriptionCard`
- `VideoDetailPlaylistCard`
- `VideoDetailCommentsCard`
- `VideoDetailOpusBody`

这些组件不改变业务数据，只负责把现有数据重新组织成单列流式结构。

### Existing Dependencies

重设计必须继续复用现有能力：

- `apiService.getVideoDetail()`
- `apiService.getLocalPlaybackMap()`
- `apiService.getLocalOpusContent()`
- `apiService.parseDownloadUrl()`
- `useVideoDownload()`
- `videoLibraryService.checkBeforeAdd()`
- `buildPlayablePages()` / `selectInitialPlayableEntry()`
- `parseLocalOpusMarkdown()`

## Responsive Rules

### Mobile

- 单列布局全宽展示
- 顶栏和主卡片间距更紧凑
- 封面卡优先占据首屏
- 操作按钮保持大触达面积
- 评论与分 P 列表继续向下流，不拆栏

### Desktop

- 仍然使用同一套单列结构
- 只增加左右留白和最大宽度
- 不恢复左右双栏信息拆分
- 通过更宽的内容容器提升阅读舒适度，而不是改变结构

### Shared Width Strategy

- 统一单列内容容器的最大宽度
- 让封面、信息、操作、正文、评论都沿同一中心轴排列
- 所有卡片在 PC 和手机上使用同一顺序

## Error Handling

- 详情拉取失败时，继续保留整页错误状态和返回按钮。
- 本地播放映射失败时，隐藏本地播放入口，不阻塞主详情展示。
- 本地图文未命中时，继续回退远端解析，不改变正文区结构。
- 评论缺失时，只隐藏评论卡，不破坏其他模块。
- 分 P 列表为空时，仅隐藏分 P 卡，不影响主内容和下载按钮。

## Data Flow

```
路由参数
  -> VideoDetailPage 拉取视频/图文详情
  -> 同步本地播放映射
  -> 同步下载状态
  -> 组装单列流式模块
  -> 依次渲染封面 / 信息 / 操作 / 正文 / 分P / 评论 / Outlet
```

图文分支的数据流保持不变，只是展示顺序改成单列阅读流：

```
本地图文优先命中
  -> 读取本地 Markdown
  -> 未命中则回退远端 parseDownloadUrl
  -> 统一进入正文流渲染
```

## Visual Direction

整体目标是“更像 B 站 App，而不是桌面后台页”：

- 封面更像主内容卡
- 信息更像帖子正文头部
- 操作更像 App 的内容页底部动作区
- 评论和分 P 像连续向下展开的内容模块
- 降低大面积硬分栏和强桌面感的存在感

### Tone

- 轻
- 紧凑
- 连续
- 有节奏
- 不拥挤

## Testing

### Functional Checks

- 视频详情页在 PC 和手机都使用同一套单列结构。
- 封面、本地播放、下载、分 P、评论、图文正文全部可访问。
- 图文页面仍优先命中本地 Markdown。
- 多 P 视频仍能逐个播放本地分 P。
- AI 子路由仍可正常挂载。

### UI Checks

- 首屏从上到下的阅读顺序自然。
- 顶栏不抢占过多高度。
- 信息卡、操作卡、正文卡之间节奏统一。
- 桌面端不再出现明显的左右双栏断裂感。
- 手机端不出现功能入口堆叠挤压。

### Regression Checks

- 下载按钮逻辑不变。
- 评论展示逻辑不变。
- 本地播放逻辑不变。
- 图文 fallback 逻辑不变。
- 现有路由和 `Outlet` 子页面不变。

## Acceptance Criteria

- PC 和手机的详情页结构一致，都是单列流式。
- 页面看起来更接近 B 站 App，而不是传统双栏网页。
- 所有现有功能入口都能在新布局中找到。
- 不需要修改后端接口才能完成这次重设计。
- 用户不会因为视觉改版而丢失任何原有信息或操作。

## Implementation Notes

- 这次实现优先在 `VideoDetailPage.tsx` 内完成布局重排，再决定是否拆分为更小组件。
- 如果需要补样式，优先使用现有设计令牌和现有卡片语义，不要引入第二套页面风格。
- 封面、信息、操作、正文、评论、分 P 的视觉层级应统一由一个页面容器控制。
- 任何新拆出的子组件都必须只做展示，不接管业务请求逻辑。

## Assumptions

- 现有视频详情页的数据字段足够支撑新的单列布局。
- 单列流式设计不会要求新增 API。
- 现有 `Outlet` 子路由仍然需要保留在详情页底部。
- 当前 App 风格的视觉基线可以作为新详情页的参考，而不是重新发明一套主题。

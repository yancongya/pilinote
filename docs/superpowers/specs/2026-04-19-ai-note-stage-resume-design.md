# AI 笔记阶段断点重跑设计

## 背景
当前 AI 笔记流水线已经从内部 `T0/T1/T2/T3` 改成语义化阶段：

- 音频获取
- 字幕生成
- NFO 读取
- Prompt 构建
- AI 分析
- 生成内容

但实际使用中仍然存在两个问题：

1. 失败后只能整条重置重跑，无法从失败点恢复
2. 用户希望能直接双击某个圆点，从该阶段开始往后重新执行

本设计的目标是为 AI 笔记流水线增加“阶段断点重跑”能力。

## 目标

### 功能目标
- 允许用户双击某个阶段圆点，选择从该阶段开始重跑。
- 重跑时保留该阶段之前的 trace 和已完成产物。
- 重跑时清空该阶段及其之后的 trace、状态和派生成果。
- 后端可根据起始阶段重建最小上下文，并继续执行后续阶段。

### 非目标
- 不重做 AI 笔记的整体流水线结构。
- 不把断点重跑扩展成通用任务调度框架。
- 不新增独立的流程编排页面。
- 不改变现有阶段展示文案。

## 方案

### 推荐方案：阶段断点重跑
用户在 AI 笔记弹窗中双击某个圆点，前端将该圆点对应的阶段标记为 `resume_from_stage`，后端据此从该阶段开始重新执行后续步骤。

特点：
- 交互直接
- 符合用户对“从报错点继续”的预期
- 可以最大化复用前面阶段的输出

### 备选方案 1：延迟重跑
双击只设置重跑起点，不立即启动；用户再次点击“开始分析”才真正执行。

特点：
- 实现更简单
- 但交互不够直接

### 备选方案 2：整条重跑但跳过缓存
表面上从某阶段继续，实际仍是整条流程重跑，只是复用前面缓存结果。

特点：
- 最容易实现
- 但不是真正的阶段恢复

## 设计

### 阶段边界
当前 AI 笔记阶段按以下顺序执行：

1. 音频获取
2. 字幕生成
3. NFO 读取
4. Prompt 构建
5. AI 分析
6. 生成内容

断点重跑必须以这个顺序为准。用户选择某个阶段后，后端从该阶段开始，重新执行该阶段及其之后的全部阶段。

### 恢复规则
当用户从某个阶段重新开始时：

- 该阶段之前的 trace 保留
- 该阶段及其之后的 trace 清空
- 该阶段及之后的中间产物按需重建
- 如果阶段有可复用输入，则直接复用
- 如果阶段依赖上游结果，则从最近的可复用结果重新构建

例如：
- 从“字幕生成”开始重跑时，保留“音频获取”结果，重新执行字幕生成、NFO 读取、Prompt 构建、AI 分析、生成内容
- 从“Prompt 构建”开始重跑时，保留字幕文本和 NFO 内容，重新构建 prompt、重新调用 LLM、重新生成内容

### 前端交互
- 双击某个阶段节点后，弹出轻量确认或直接触发重跑。
- 重跑状态开始后，时间轴显示当前重跑起点。
- 失败节点再次出现时，允许继续双击重跑。
- 右键菜单不是必需项，先不做。

### 后端接口
需要增加一个按阶段重跑的接口，输入至少包含：

- `note_id`
- `resume_from_stage`

后端执行时需要：

- 读取 note 现有 trace
- 截断 `resume_from_stage` 之后的 trace
- 标记当前控制状态为 `running`
- 重新进入对应阶段函数

### 状态持久化
建议在 `note.meta.control` 中扩展以下字段：

- `state`: `running | paused | cancelled | completed`
- `current_stage`: 当前执行阶段
- `resume_from_stage`: 断点重跑的起点阶段

这样前端在刷新后也能知道当前任务是从哪个阶段恢复的。

## 错误处理

### 阶段内失败
如果某阶段失败，错误必须落在当前阶段节点，不允许只落在统一 `ERROR` 节点。

### 重跑失败
如果用户从某阶段重跑，但该阶段再次失败：

- 保留该阶段之前的 trace
- 重新记录当前失败节点
- 不影响前面的已完成阶段

### 取消与重置
- 暂停只冻结当前执行，不改变已完成 trace。
- 取消终止当前执行并将 note 标记为失败。
- 重置清空当前 note 的执行状态并从头开始。

## 验证标准

### 交互
- 双击任意阶段节点后，能够从该节点开始重新分析。
- 从中间阶段重跑后，前面阶段 trace 不会丢失。

### 执行
- 从“字幕生成”重跑时，音频获取结果可复用。
- 从“Prompt 构建”重跑时，字幕和 NFO 结果可复用。
- 从“AI 分析”重跑时，前面阶段不再重复执行。

### 稳定性
- 重跑不应遗留旧的后台 ASR 进程。
- 重跑不应把 provider 配置回退到错误的默认值。
- 空值和部分失败输入不应触发 `strip` 类运行时错误。

## 约束
- 不新增独立的任务编排系统。
- 不改变现有阶段命名体系。
- 不把“断点重跑”扩展成通用 DAG 调度。
- 不引入用户必须手动选择的复杂恢复向导。

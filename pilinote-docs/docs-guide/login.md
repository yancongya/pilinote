# 登录与账号

PiliNote 依赖 B 站登录态来读取收藏夹/稍后再看/历史/订阅等。核心原则是：登录态要“可持久化、可切换、可排错”。

## 登录态是什么

常见字段：

- `SESSDATA`：最核心的登录 cookie
- `bili_jct`：部分操作需要

项目通常会把 cookie 持久化到本地数据库中（便于重启后继续使用）。

## 多账号

如果你使用多个账号，建议明确：

- 当前激活账号是谁
- 该账号的 cookie 是否仍然有效

## 失效与风控（你会遇到的）

这些现象通常意味着登录态失效或触发风控：

- 扫描列表返回空 / 403
- 下载/解析频繁失败
- 需要验证码/人机验证

建议：

- 降低扫描频率与并发
- 避免短时间高频请求
- 重新获取 cookie 后再继续

## 排错建议（最有效的三件事）

1. 在设置页确认“当前账号”与“cookie 状态”显示正常
2. 先跑一次“手动解析单个 BV”验证链路
3. 如果列表类接口异常但单 BV 正常，重点排查：风控、频率、是否有订阅/历史读取权限
